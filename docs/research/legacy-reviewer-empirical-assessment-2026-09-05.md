# legacy reviewer: empirical assessment, 2026-09-05

## What the strongest evidence actually says

The holdout is the first controlled evidence on `v5b-1`: 15 retrospective runs on five targets, one three-round publishing lifecycle, six lower-effort runs, four verification-disabled runs, and six comparator runs. Models and effort were checked against transcripts; mirrors excluded future commits; ground truth and bands were specified before running. Those are material improvements over the development corpus. The grid was reduced for cost and the higher-model-tier experiments never ran. [Method](prototype-runs-holdout/README.md), [execution and cuts](prototype-runs-holdout/evaluation.md#what-ran-and-what-was-cut).

| Capability | Observed result | Interpretation for a one-shot review |
| --- | --- | --- |
| Avoid factually false findings | No false published findings adjudicated across the 15 main retrospective runs | Encouraging precision evidence, not a general precision guarantee; severity and optionality can still be wrong |
| Find the production concurrency defect | Hyper: one full success, one shutdown-only projection, one acquittal in three runs | Even an independently verified review can confidently approve a real regression |
| Recover required changes outside the diff | Typeshed: central missing re-export found in one of three runs; comparator found all three selected omissions in each of three runs | Complete diff inspection is not requirement coverage |
| Review tests as executable behavior | Cobra first review missed all three ground-truth items and suggested named subtests while the new test was red | Attention went to conventional form instead of evaluating the test's operations and assertions |
| Calibrate action and priority | Every Polars run escalated a true item above its predetermined band | Zero false facts does not imply low author burden or correctly actionable advice |
| Surface open questions | UV deferred API question: zero of three; Polars benchmark question: zero of three | The channel exists but admission and discovery prevent it from doing its intended job |
| Publish safely and retain state | Cobra re-review classified the prior finding, posted its reply, and refused a stale-head write | The workflow shell has demonstrated value despite limited bug recall |

All cells are from the [target-level evaluation](prototype-runs-holdout/evaluation.md). The [Hyper seed-3 payload](prototype-runs-holdout/a-hyper-3952/v5b-seed3-payload.md) explicitly says issue fit is met and the non-shutdown behavior was verified independently. The [Cobra first-review payload](prototype-runs-holdout/f-cobra-1938/v5b-seed1-r1-payload.md) calls coverage complete and publishes only the subtest suggestion. These are examples of the precise output a user would receive, not just private reasoning errors.

## Cost and latency: corrections needed before choosing an architecture

Use target-matched comparisons. The headline $8.88 versus $3.62 medians compare a comparator run only on Typeshed and UV with the integrated reviewer across additional targets, including cheap Cobra follow-up/probe rounds. The method itself says cross-target billed cost is not comparable. On comparable targets, the estimated production-shaped medians are:

| Target | Current high-effort primary | Medium primary, high verifier | Historical comparator |
| --- | ---: | ---: | ---: |
| Raft | $2.90 | $1.80 (38% lower) | Not run |
| Typeshed | $4.25 | $2.51 (41% lower) | $9.13 (2.15× current) |
| UV | $3.05 | Not run | $6.87 (2.25× current) |

[Per-target billed accounting and comparison boundaries](prototype-runs-holdout/comparison-data.md). The comparator's additional omissions are real, but its cost premium bought a bundle: another search process, mandatory requirement restatement, more verification, and expensive report-shape repair. Repeated seeds support a repeatable advantage on those targets; they **do not isolate requirement restatement as the sole cause**, as the evaluation sometimes claims. A restatement-only integrated-reviewer arm is the necessary ablation.

The reported `Wall` total is **summed transcript spans, not end-to-end elapsed time**. This is explicit in [transcript_usage.py](https://github.com/kamui/code-review-bench/blob/main/bench/tools/transcript_usage.py), including its docstring and `Usage.absorb`. Parent transcript spans include waiting for foreground child calls; summing parent and child double-counts that interval. For example, Hyper seed 3 is reported as 52:06, but its parent span is 38:18 and its waited verifier is 13:48. [Primary record](prototype-runs-holdout/a-hyper-3952/v5b-seed3-run.md).

As a more appropriate, still approximate latency measure, medians of the first/root transcript span in the archived run preambles are: Raft 20.7 minutes at high versus 16.1 at medium; Typeshed 22.4 versus 15.7, comparator 51.5; UV 15.8, comparator 42.0. These exclude time before the first assistant timestamp and include report generation. Future runs need root dispatch-to-payload and root dispatch-to-publication timestamps. Summed spans remain useful as agent time, with that label.

The historical assumption that removing research output saves 15–25% is superseded by the holdout's estimated report-output shares: 3.4% for the main arm and 4.8% for medium. But “production-shaped” remains an estimate: it subtracts report bytes/4 at the output rate, not the thinking, cache replay, and extra requests caused by research instructions. The main cost levers are request count, replayed context, and generated output including reasoning; final context size is not billed usage. [Metering definition](prototype-runs-holdout/README.md#metering-per-run), [recorded shares](prototype-runs-holdout/comparison-data.md#per-arm--ranked-on-billed-production-shaped-cost).

## Important limits and interpretation changes

- **All holdout reviewers were forbidden to execute target code.** Only their own helper scripts were allowed; Raft tests were executed by the adjudicator. The shipped skill permits safe, focused checks. Therefore Cobra's miss demonstrates a static-inspection failure under an artificial restriction, not the failure of a workflow that actually ran its new test. The next production-shaped arm should allow proportionate tests, bounded reproducers, or explicit operational traces when execution is unavailable. [Execution restriction](prototype-runs-holdout/README.md#mirror-and-clones), [Cobra disclosure](prototype-runs-holdout/f-cobra-1938/v5b-seed1-r1-run.md).
- **The no-verifier arm is not a normal single-reviewer competitor.** It simulates mandatory verification being unavailable and withholds affected findings. It measures discovery and fail-closed behavior; published-output comparisons cannot estimate the precision/recall of publishing primary-confirmed findings under an alternative admission policy. Four single-seed cells also cannot establish verification's average incremental value. [Ablation specification](prototype-runs-holdout/README.md#arms).
- **One-shot recall must be measured per run.** The old retirement condition uses the union across three runs. A production user pays for one review and never sees that union. Measure per-seed defect recall, severity-weighted recall, and the rate of no useful finding on buggy changes. Keep optional questions separate from actual bugs; successful reproduction of a deferred naming question should not carry the same product weight as catching the Hyper livelock. [Scoring and retirement criteria](prototype-runs-holdout/README.md#scoring).
- **Small selected samples do not support architecture-wide guarantees.** Several runs on one target test stochastic variability, not independent repository generalization. The holdout is now development data for #119–#124. Another successful run on Hyper can validate the repair mechanism, but adoption needs at least some unseen targets. Ground truth gained legitimate new findings after running; those additions should be scored blind across arms under a consistent rule. [Adjudication](prototype-runs-holdout/evaluation.md).
- **One formal pass/fail statement overstates its preregistration.** Criterion 2 in the README says fewer than three false-acquittal occurrences is `not decidable`. The evaluation calls it `FAIL` on zero re-opens out of two. Both observed mistakes escaped correction, which is a clear negative result, but the formal threshold was not decidable under its own rule. [Criterion](prototype-runs-holdout/README.md#success-criteria), [verdict](prototype-runs-holdout/evaluation.md#success-criteria-for-v5b).
- **The effort decision has moved beyond the checked-in evaluation.** The live [#124](https://github.com/kamui/skills/issues/124) records a September 5 maintainer decision changing the rule to published outcomes, with the recovered Raft ledger error disclosed as a post-hoc deviation. It requires three reasoning-heavy Hyper runs before changing the recommended default. The local evaluation still records the original rule as unmet. Report both; do not present the revised rule as preregistered. Its evidence supports the measured shape—medium primary, high verifier—not invented risk-based effort tiering.

## Recommended experimental sequence

1. **Fix discovery before buying duplication:** implement requirement-first, version-pinned public-surface enumeration (#123) and operational tracing of changed tests (#122). Use compact, bounded search plans and preserve the current evidence/admission boundary. Their hypotheses address observable misses and mostly fit the existing integrated context.
2. **Repair safety-ruling handling (#119), then measure it:** require contradictions to affect dispositions, distinguish “candidate refuted” from “surface safe,” and keep any second pass bounded. It deserves priority for quality, but another verifier must demonstrate correction rather than merely exercise a new rule.
3. **Run the medium/high validation in #124:** the measured 38–41% saving is stronger cost evidence than any speculative replica estimate. Include per-run useful recall and new failures, not only published status or union recall. Treat harness/model portability as unvalidated outside the measured configuration.
4. **Add a production-shaped evidence arm:** same input and budget, permit focused execution, record assertion traces where no test can run, and compare useful bugs per billed dollar. This is a new strategy in evidence acquisition, achievable without replacing the publishing skill.
5. **Only then test a second independent search:** prefer a bounded complementary obligation/caller search or stronger verifier control before a complete replica. If pursuing [#88](https://github.com/kamui/skills/issues/88), compare against a single parent at the same model tier and effort. The existing holdout never ran the stronger-tier controls that ticket assumes, and its own text admits no evidence of a weaker model finding what the stronger missed. Count unique true actionable results and their price, not routed disagreements alone. Do not promote from three seeds on one already-used target.

Questions about benchmarking and explicitly deferred preferences (#121/#120) are coherent product features, but rank below missed executable bugs and incomplete required surfaces for this user's stated objective. Early verifier dispatch (#70) is lower still: it primarily targets latency, can consume the follow-up budget sooner, and should wait for honest elapsed-time instrumentation. Coordinate fidelity (#84) and pricing-tier accounting (#97) are useful bounded maintenance, not substitutes for better bug discovery.
