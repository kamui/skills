### Finding 1 — `error-tests/no-stack-double`

- **Priority / action:** P2 / consider (`blocking=false`)
- **Kind:** bug (test-file defect; routed under the rubric's "changed test is code under review with its own standard" clause, §"Complete inspection")

- **Fix location:** same as anchor (omitted per contract: "Omit `fix` when it is the anchor")
- **Claim:** The test named `'creates new stack if original error has no stack'` (lines 57–64) now constructs its double with `const original = new Error('original');` instead of the base version's `const original = { message: 'original' };`. A real `Error` instance always carries a populated `.stack` (V8/Node behavior), so `GraphQLError`'s constructor takes its `if (originalError && originalError.stack)` branch (`src/error/GraphQLError.js:187-193`) — reusing `originalError.stack` — rather than the `Error.captureStackTrace` fallback (`src/error/GraphQLError.js:194-200`) the test's own name and comment claim to exercise.
- **Trigger:** Any call of `new GraphQLError(msg, ..., originalError)` where `originalError` is a genuine `Error` instance (as opposed to a stack-less double).
- **Impact:** The test's assertions (`e.stack` is a string, `e.name`/`e.message`/`e.originalError` equality) hold identically whichever branch runs, so the test passes vacuously and no longer verifies the `Error.captureStackTrace` fallback path it is named for. A future regression in that fallback (e.g. removing the `else if (Error.captureStackTrace)` branch or breaking it) would go undetected by this suite.
- **Change requested:** Give `original` a double that genuinely lacks `.stack` — e.g. `const original: any = { message: 'original' };`, the same `: any` escape hatch this very PR already uses two files over in `src/error/__tests__/locatedError-test.js` (lines 24 and 27 of the head) — instead of `new Error('original')`.
