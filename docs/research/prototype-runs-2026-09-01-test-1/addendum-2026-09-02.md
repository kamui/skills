- **v5a / `shortlist-narrow/SKILL.md:46`: fix confirmed working.** 0-for-1 pre-fix (per handoff 6, on
  this target) → 1-for-1 post-fix, via the exact repo-wide case-insensitive sweep mechanism the fix

  pre-fix Sonnet replicates published zero findings) — this run cannot speak to that, being n=1.
- **v2a / `search-bundle-format.md:208`: fix confirmed working, both runs.** Run 1's Requirements
  finder ran handoff 5's two-leg sweep and found it; run 2 found it on both axes (Requirements via
  changed-contract row 1's old-fragment sweep, Code via its new sync-drift section). Verifier-confirmed
  each time.
- **v2a / `shortlist-narrow/SKILL.md:46`: run-1 miss diagnosed by DESIGN.md §C9; run 2 finds it —
  but on a different model, so the two runs do not isolate the fix.** Run 1 ran on
  `claude-sonnet-5` and run 2 on `claude-fable-5-1` (see the model table above). The skill commit
  and the model both changed between them, so this pair cannot attribute the recovered recall to
  `940aa2c` on its own. What survives the confound: the fix's *mechanism* is visible in run 2's
  output — the changed-contract list was returned, row 3 is the closed-list → open-rule shape C9
  added, and that row's old-fragment sweep is what surfaced the item — and the skill author's own
  replication (3/3 on the restructured rubric vs 1/5 unchanged) is independent evidence for the fix.
  A clean before/after on one model is still missing. Detail: Run 1 (skill `5db5903`) missed this item on both axes, absent from both ledgers — the
  first miss on this target across six prior runs. The skill author's replication (DESIGN.md §C9:
  unchanged rubric 1/5 Requirements, 0/5 Code; declarative first attempt 0/3; restructured
  changed-contract-list rubric 3/3 on Requirements) attributed it to the paired-sweep rule keying on
  vocabulary/enum changes only, so a closed-list → open-rule change was never written down as a
  contract to sweep — the run-1 addendum's "attention cost" hypothesis, sharpened. `940aa2c` makes
  the finder write the changed-contract list first and explicitly names that shape. Run 2 (skill
  `87c68a9`): the Requirements finder's changed-contract row 3 swept `price, stock, delivery` and
  surfaced the item; the Code finder raised it independently; verifier confirmed; merged, P2
  `consider`. n=1 post-fix on this target, matching the author's 3/3 replication. No further
  investigation indicated on the mechanism itself; handoff 7 (`investigate-v2a-narrow-miss`) is
  moot. A model-matched re-run of v2a run 2 would close the confound.
- **v2a / `validate-completion.py:2949`: third drift, first found by a prototype run.** The same
