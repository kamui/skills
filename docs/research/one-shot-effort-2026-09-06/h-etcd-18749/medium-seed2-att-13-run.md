- **Anchor:** `server/etcdserver/txn/txn_test.go:343` (RIGHT side; the line `b, bePath := betesting.NewDefaultTmpBackend(t)` inside `TestWriteTxnPanicWithoutApply`, an added/changed line in the diff hunk `@@ -336,38 +339,47 @@`).

Because `txn.go`'s fix removes `txnWrite.End()` from the write-failure path (the PR's whole point), a panic taken by this test leaves the backend's shared `batchTx.Mutex` **locked**, since `storeTxnWrite.End()` — the only caller of `tw.tx.Unlock()` — is never reached. The backend's periodic-commit goroutine (`backend.go:426 (*backend).run` → `batch_tx.go:255 (*batchTx).safePending()` → `t.Mutex.Lock()`) therefore blocks forever trying to reacquire that same mutex once the ticker fires, and the underlying bbolt db file descriptor (opened via `betesting.NewDefaultTmpBackend`) is never closed because nothing calls `betesting.Close`/`b.Close()` for this test.
- **Verification status:** Not independently verified — not required. This is a `consider`/`maintainability` hygiene candidate; per `references/review-rubric.md` Complete inspection §, "A hygiene candidate is `maintainability` for routing and `consider` for action, so it never qualifies for mandatory verification on its own." I falsified it myself with full citations (below) rather than deferring to a verifier, which the skill does not require here. Marked `primary-confirmed` in my private ledger.
- **Evidence (decisive):**
  - `server/etcdserver/txn/txn_test.go:343` — new `b, bePath := ...` line has no matching `defer`/`t.Cleanup` close, unlike sibling call sites at `txn_test.go:285-288`, `:311-312`, `:386-387` (established via a batched `grep -n` over the whole file for `betesting\.(Close|NewDefaultTmpBackend|NewTmpBackend)`, one call, not one per site).

  - `server/storage/backend/batch_tx.go:87-114` (`lock`/`Unlock`) and `:255-259` (`safePending`) — both take the same `t.Mutex`, so a leaked lock blocks the periodic committer.
